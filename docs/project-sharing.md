# 프로젝트 소유자의 Notion 연결 공유

Notion 워크스페이스 게스트가 OAuth를 설치할 필요 없이, 모음 프로젝트 소유자가 승인한 페이지의 기록을 모음 프로젝트 멤버가 함께 조회합니다. Notion 자체의 설치 권한이나 페이지 접근 권한을 우회하지 않습니다.

## 적용 순서

1. 백엔드 프로젝트 루트의 PowerShell에서 새 테이블만 생성합니다.

   ```powershell
   .\.venv\Scripts\python.exe -m scripts.setup_project_members_db --apply
   ```

   기존 프로젝트·사용자·Notion 연결·기록은 유지합니다. 이 테이블 생성 후 백엔드를 배포해야 합니다. 새 코드의 프로젝트 목록/조회가 이 테이블을 사용합니다.

2. 프로젝트 소유자가 모음에 로그인하고 Notion 계정 연결을 승인합니다. 해당 Notion 워크스페이스에서 연결 설치 권한이 있는 계정으로 프로젝트에 등록할 페이지를 선택해야 합니다.
3. 기존 **소유자의 프로젝트**에 대상 Notion 페이지 URL을 등록합니다. 게스트가 자기 계정으로 새 프로젝트를 만드는 방식은 이 연결을 공유하지 않습니다.
4. 팀원도 모음에 회원가입합니다. 소유자가 Swagger에서 아래 요청으로 팀원을 추가합니다. 이 작업은 해당 프로젝트의 모든 서비스 기록과 Story를 공유하므로 대상을 확인합니다.

   ```http
   POST /api/projects/{project_id}/members
   Authorization: Bearer <소유자의 모음 로그인 토큰>
   Content-Type: application/json

   {"email":"팀원이 모음에 가입한 이메일"}
   ```

5. 팀원이 자기 모음 계정으로 로그인하고 프로젝트 목록을 새로고침하면 공유받은 프로젝트가 표시됩니다. 개인 Notion 연결 상태가 `connected:false`여도 공유 프로젝트 조회/Notion 새로고침에는 영향을 주지 않습니다.
6. 페이지를 수정하고 공유 프로젝트에서 Notion 새로고침을 누릅니다. 첫 수집은 비교 기준을 저장하고, 이후 수집부터 차이를 기록합니다. 소유자와 팀원은 같은 DB 기록을 봅니다.

## API와 권한

| 작업 | 소유자 | 등록된 팀원 | 그 외 사용자 |
|---|---|---|---|
| 프로젝트 목록·상세·대시보드·연결 상태 조회 | 허용 | 허용 | 차단 |
| 기록·Story 조회·내보내기·수집 이력 조회 | 허용 | 허용 | 차단 |
| Notion 새로고침 | 소유자 연결 사용 | 소유자 연결 사용 | 차단 |
| URL·프로젝트 설정 변경·Story/기록 편집·삭제 | 허용 | 차단 | 차단 |
| GitHub·Figma 수집 실행 | 허용 | 차단 | 차단 |
| 팀원 목록·추가·삭제 | 허용 | 차단 | 차단 |
| 소유자 Notion 토큰 조회 | 제공 안 함 | 제공 안 함 | 제공 안 함 |

- `GET /api/projects/{project_id}/access`: `role`, `can_manage`, `can_sync_notion`, `notion_connection_owner_id`를 반환합니다. 프론트는 `can_manage:false`이면 소유자용 연결 승인/설정 편집/삭제 동작을 숨기고, 오류 시 소유자에게 페이지 승인을 요청하도록 안내해야 합니다.
- `GET /api/projects/{project_id}/members`: 소유자에게 추가된 팀원 목록을 반환합니다. 소유자는 암묵적으로 접근하므로 목록에 별도로 저장하지 않습니다.
- `POST /api/projects/{project_id}/members`: 기존 활성 회원의 이메일로 추가합니다. 같은 회원을 다시 추가해도 중복되지 않습니다. 이메일을 보내거나 Notion 권한을 변경하지 않습니다.
- `DELETE /api/projects/{project_id}/members/{user_id}`: 이후 요청부터 공유 접근을 차단합니다. 이미 시작된 요청이나 이미 내려받은 자료는 회수하지 않습니다.

## 프론트 연결 시 주의

프로젝트 선택과 기존 기록 조회/Notion 새로고침 API 경로는 그대로 사용합니다. 별도 프론트 팀원 초대 화면은 아직 없으므로 위 Swagger API로 팀원을 등록합니다. 개인 Notion 연결 상태를 프로젝트 접근 허용 조건으로 사용하지 마세요. 공유 프로젝트의 새로고침에 사용하는 인증은 항상 프로젝트 소유자의 것입니다.

현재 소유자별 Notion 연결은 한 워크스페이스만 저장합니다. 소유자가 다른 워크스페이스로 다시 연결하면 기존 프로젝트의 페이지 접근도 영향을 받을 수 있습니다. 소유자 연결이 해제되거나 페이지 승인이 취소되면 새 수집은 실패하지만 이미 DB에 저장된 기록은 유지됩니다.
