# 로그인 만료와 외부 서비스 재연결

MOEUM 로그인은 JWT가 아닌 서버 DB 세션입니다. 이메일 로그인과 GitHub 로그인 모두
로그인 또는 마지막 갱신 시점부터 30일 동안 유효합니다. 화면이 보이는 동안 15분마다
서버에서 갱신하므로 계속 사용하는 경우 1시간이 지나도 로그인이 유지됩니다.
30일 동안 갱신하지 않았거나 로그아웃·비밀번호 변경·계정 비활성화로 폐기된 세션은
복원하지 않습니다.

## 브라우저를 다시 열었을 때

로그인·GitHub 코드 교환·갱신 성공 시 30일짜리 `moeum_session` 쿠키를 설정합니다.
쿠키는 HttpOnly, SameSite=Lax, 호스트 전용이며 HTTPS에서 Secure를 사용합니다.
브라우저가 닫혀도 쿠키가 유지되므로 홈 화면 또는 보호 화면을 다시 열면
`POST /api/auth/refresh`로 기존 서버 세션을 복원합니다.

장기 보관에는 HttpOnly 쿠키를 사용합니다. 기존 API와의 호환을 위해 브라우저 탭의
`sessionStorage`에는 같은 세션의 Bearer 토큰과 만료 시각을 캐시합니다. 따라서 현재 탭의
토큰 캐시는 자바스크립트가 읽을 수 있습니다.
`localStorage`에는 로그인 토큰을 저장하지 않습니다.

인증 요청은 개발·운영 모두 같은 사이트의 `/backend/api/auth/*`를 사용합니다.
Vite 프록시 및 `vercel.json`의 외부 rewrite가 Render로 전달하므로 다른 사이트 쿠키를
차단하는 브라우저에서도 로그인 유지 쿠키를 사용할 수 있습니다. 운영 BE 주소를 바꾸면
Vercel rewrite의 대상 주소도 함께 변경해야 합니다.

## 프론트엔드 동작

- 로그인 응답의 `expires_in`으로 계산한 만료 시각을 기존 세션 토큰과 함께
  `sessionStorage`에 저장합니다. 요청 지연 때문에 유효기간을 늘리지 않도록
  로그인 요청 시작 시각을 기준으로 계산합니다.
- 보호 API의 401은 전역 로그인 만료로 처리합니다. 해당 세션의 진행 중 요청을 취소하고
  보호 화면을 해제해 자동 조회를 중단한 뒤, 로그인 화면에 재로그인 안내를 표시합니다.
- 이메일·비밀번호 로그인 실패와 GitHub 일회용 코드 교환 실패의 401은
  각 로그인 폼에서 처리하며 기존 세션을 만료시키지 않습니다.
- 화면 최초 진입, 15분 주기, 탭 복귀 시 서버 세션을 갱신하고 `/api/auth/me`를 확인합니다.
  로컬 만료 시각이 임박한 보호 요청도 먼저 갱신합니다. 네트워크 오류만으로 기존 로그인은
  삭제하지 않습니다.
- 기존 1시간 세션도 아직 서버에서 유효하면 갱신 API가 30일 세션으로 연장하고 쿠키를
  설정합니다. 이미 폐기되었거나 서버에서 만료된 세션은 되살리지 않습니다.
- 동시에 발생한 갱신은 하나의 요청으로 합칩니다. 일반 조회는 세션 만료 시각을
  변경하지 않으며, 갱신 성공만 서버의 만료 시각과 쿠키 유효기간을 연장합니다.
- 이전 로그인에서 지연된 응답이 도착해도 새 로그인 세션은 만료시키지 않습니다.
- GitHub 연결 만료 409는 저장된 커밋을 유지하고 `GitHub 다시 연결`을 제공합니다.
  기존에 연결한 GitHub 계정으로 다시 로그인하는 현재 OAuth 흐름을 사용합니다.
  일시적 장애에는 `다시 시도`를 제공합니다.

## 백엔드 진단

보호 API 인증 실패 응답은 기존 `detail` 문자열과 401 상태를 유지하며
`X-Auth-Error` 헤더를 추가합니다.

| 코드 | 의미 |
| --- | --- |
| `AUTH_REQUIRED` | Bearer 인증 정보 없음 |
| `SESSION_NOT_FOUND` | 토큰에 대응하는 사용자·세션을 찾을 수 없음 |
| `SESSION_EXPIRED` | 저장된 세션의 만료 시각 경과 |
| `ACCOUNT_INACTIVE` | 활성 상태가 아닌 계정 |
| `INVALID_CREDENTIALS` | 이메일 로그인 자격 증명 오류 |

`SESSION_NOT_FOUND`만으로 삭제된 세션과 잘못된 토큰을 구분할 수는 없습니다.
GitHub 개인 토큰이 거부되면 MOEUM 401과 구분해 409 및
`X-Integration-Error: GITHUB_RECONNECT_REQUIRED`를 반환합니다.

서버가 생성한 `X-Request-ID`로 응답과 인증 실패 로그를 연결합니다. 로그에는
실패 사유, 확인 가능한 사용자 ID, 요청 ID, 메서드와 경로만 기록합니다.
Authorization 헤더, 토큰, 토큰 해시, 비밀번호와 URL 쿼리는 기록하지 않습니다.
관련 응답 헤더는 CORS를 통해 프론트엔드에서 읽을 수 있습니다.

## 검증과 운영 반영

- BE: `python -m pytest -q` — 임시 SQLite DB 및 모의 외부 응답 사용.
- FE: `npm test`, `npm run build`.
- FE 브라우저: `npm run test:auth-browser` — 로컬 서버와 모의 API 응답 사용.
  실제 계정으로 로그인하거나 운영 DB 및 외부 서비스에 요청하지 않습니다.

DB 스키마 변경이나 마이그레이션은 없습니다. BE의 헤더 추가는 기존 FE와 호환되며,
FE는 기존 GitHub 만료 문구도 처리합니다. 갱신은 기존 행의 유효성을 다시 확인하는
조건부 UPDATE이며 삭제된 세션 행을 재생성하지 않습니다. 갱신 쿠키 요청에는 허용된
`Origin`이 필요하며, Bearer를 가진 API 클라이언트는 Origin 없이 갱신할 수 있습니다.
허용되지 않은 Origin은 인증 정보 유무와 관계없이 거부합니다.

운영에는 새 BE의 갱신 API를 먼저 준비한 뒤 FE 및 Vercel rewrite를 함께 반영합니다.
새 FE는 `/api/auth/refresh`가 없는 이전 BE와 호환되지 않습니다. 운영 반영 전에는 두
저장소의 실제 배포 브랜치와 커밋을 별도로 확인합니다.
